# Play Store 단계별 테스트 및 출시 가이드

기업족보 앱을 **내부테스트 → 비공개 테스트 → 프로덕션** 순서로 배포하는 과정을 단계별로 설명합니다.

> **참고**: 기본 설정(Play Console 계정 생성, 앱 등록, 키스토어, AAB 빌드 등)은 기존 [PLAY_STORE_RELEASE_GUIDE.md](./PLAY_STORE_RELEASE_GUIDE.md)를 참조하세요.

---

## 단계 흐름

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  내부테스트   │───▶│  비공개 테스트 │───▶│  프로덕션 신청 │
│  (심사 없음)  │    │  (심사 필요)  │    │  (심사 필요)  │
│  최대 100명   │    │  그룹별 100명 │    │  전체 공개    │
└──────────────┘    └──────────────┘    └──────────────┘
```

> ⚠️ **신규 개발자 계정 주의사항**: Google Play는 신규 계정에서 프로덕션 출시 전에 **비공개 테스트를 최소 20명의 테스트자가 2주 이상 참여**했을 때를 요구합니다. 이를 무시하면 프로덕션 제출이 차단됩니다.

---

## 사전 준비

모든 단계 공통으로 AAB 파일이 필요합니다.

```powershell
# JAVA_HOME 설정
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"

cd packages\web

# 웹 빌드 + cap sync + AAB 생성
npm run build
npx cap sync android
cd android
.\gradlew bundleRelease
```

생성된 파일:
```
packages/web/android/app/build/outputs/bundle/release/app-release.aab
```

## Stage 1: 내부테스트

심사 없이 즉시 배포 가능한 단계입니다. 개발자 본인과 주변 소수 테스트자로 기본 동작을 확인하는 용도입니다.

### 1.1 내부 테스트자 추가

Play Console에서 테스트자를 먼저 등록해야 합니다.

```
Play Console 좌측 메뉴
└── 설정
    └── 개발자 계정 설정
        └── 사용자 및 권한
            └── [테스트자 추가]
```

- 추가할 테스트자의 **Google 계정 이메일**이 필요합니다.
- 최대 **100명**까지 추가 가능합니다.
- 추가된 테스트자는 앱 전체에 대한 내부 테스트자로 됩니다.

### 1.2 AAB 업로드

```
Play Console 좌측 메뉴
└── 앱 (기업족보)
    └── 릴리스
        └── 내부테스트
            └── [새 버전 만들기]
                └── App Bundle → app-release.aab 업로드
```

업로드 후 아래 항목을 채웁니다:

| 항목 | 입력 예시 |
|------|-----------|
| 버전 이름 | 0.1.0-internal |
| 출시 노트 | 내부 테스트용 초기 빌드 |

### 1.3 검토 및 배포

- **심사 없이** 즉시 **[배포]** 클릭 가능합니다.
- 배포 후 테스트자 설치 링크가 자동 생성됩니다.

### 1.4 테스트자 설치

생성된 설치 링크를 테스트자에게 공유하면 됩니다.

```
내부테스트 화면 → 테스트자 링크 복사 → 테스트자에게 전달
```

테스트자 측 절차:
1. 공유된 링크를 핸드폰 브라우저에서 열기
2. Google 계정으로 로그인 (Play Console에서 추가된 계정)
3. **테스트자로 참여** 클릭
4. Play Store에서 앱 다운로드 및 설치

### 1.5 테스트 포인트

내부테스트에서 확인할 사항:

- [ ] 앱 설치 및 실행 여부
- [ ] 메인 목록(기업 리스트) 로드
- [ ] 계열사 트리 탐색
- [ ] 검색 기능 동작
- [ ] 광고 표시 여부 (테스트 광고 ID 사용 중이면 테스트 광고가 정상 표시되는지 확인)
- [ ] 앱 충돌 없음 확인

## Stage 2: 비공개 테스트

비공개 테스트는 더 많은 테스트자를 구성하고 Google의 심사를 거쳐 배포하는 단계입니다. **프로덕션 출시 전 필수 단계**입니다 (신규 계정 기준).

### 2.1 테스트 그룹 생성

```
Play Console 좌측 메뉴
└── 앱 (기업족보)
    └── 릴리스
        └── 비공개 테스트
            └── 테스트자 관리
                └── [테스트 그룹 생성]
```

- 그룹 이름 예시: `beta-testers`
- 테스트 그룹은 이메일 목록 단위로 관리됩니다.

### 2.2 테스트자 구성

테스트 그룹에 테스트자 이메일을 추가합니다. 프로덕션 출시를 위해 **최소 20명**을 구성해야 합니다.

```
테스트 그룹 (beta-testers)
├── tester01@gmail.com
├── tester02@gmail.com
├── ...
└── tester20@gmail.com   ← 최소 20명
```

> 테스트자는 본인이 직접 opt-in (참여 신청)해야 합니다. 단순히 그룹에 이메일을 추가하는 것만으로는 충분하지 않습니다.

### 2.3 AAB 업로드 및 심사 제출

```
Play Console 좌측 메뉴
└── 앱 (기업족보)
    └── 릴리스
        └── 비공개 테스트
            └── [새 버전 만들기]
                └── App Bundle → app-release.aab 업로드
```

업로드 후 항목 작성:

| 항목 | 입력 예시 |
|------|-----------|
| 버전 이름 | 0.2.0-beta |
| 출시 노트 | 비공개 테스트용 빌드. 피드백 환영합니다. |

작성 완료 후 **[검토를 위해 제출]** 클릭합니다.

### 2.4 심사 결과 확인

- 심사 기간: 보통 **1~3일** (프로덕션보다 빠름)
- 심사 완료 후 배포 가능 상태로 변합니다.
- 거부 시 사유가 표시되며, 수정 후 재제출 가능합니다.

### 2.5 테스트자 opt-in 및 설치

심사 통과 후, 테스트자에게 opt-in 링크를 공유합니다.

```
비공개 테스트 화면 → 테스트자 링크 복사 → 테스트자에게 전달
```

테스트자 측 절차:
1. 공유된 링크를 핸드폰 브라우저에서 열기
2. **테스트자로 참여** 클릭 (opt-in)
3. Play Store 앱 페이지로 이동 후 다운로드

### 2.6 테스트자 참여 현황 확인

```
비공개 테스트 화면
└── 테스트자 그룹 → 참여 상태 열
    ├── 참여 완료 ✔
    ├── 미참여
    └── ...
```

프로덕션 신청 전에 **최소 20명이 참여 완료**된 상태임을 확인합니다.

### 2.7 테스트 포인트

내부테스트와 동일한 항목 외에 추가로 확인:

- [ ] 다양한 기기 (제조사, 해상도)에서 동작 확인
- [ ] 네트워크 불안정 상황에서의 동작
- [ ] 테스트자 피드백 수집 및 버그 수정
- [ ] 광고 ID를 테스트 ID에서 **실제 ID로 변경** (프로덕션 빌드 준비)

## Stage 3: 프로덕션 신청

공개 출시 단계입니다. 전체 사용자에게 앱이 공개됩니다.

### 3.1 프로덕션 빌드 준비

프로덕션 배포 전에 반드시 아래 사항을 실제 값으로 변경합니다.

**AndroidManifest.xml** (`packages/web/android/app/src/main/AndroidManifest.xml`):
```xml
<meta-data
    android:name="com.google.android.gms.ads.APPLICATION_ID"
    android:value="ca-app-pub-9167710302823457~2889628387"/>
```

**ad-service.ts** (`packages/web/src/services/ad-service.ts`):
```typescript
const BANNER_AD_ID = PROD_BANNER_ID  // 테스트 ID가 아닌 실제 ID
```

변경 후 다시 빌드합니다:
```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
cd packages\web
npm run build
npx cap sync android
cd android
.\gradlew bundleRelease
```

### 3.2 스토어 등록정보 확인

프로덕션 제출 전 아래 항목이 모두 완료되어 있는지 확인합니다.

| 항목 | 상태 |
|------|------|
| 앱 이름 | 기업족보 |
| 간단한 설명 (80자 이내) | |
| 자세한 설명 (4000자 이내) | |
| 앱 아이콘 (512x512 PNG) | |
| 그래픽 이미지 (1024x500) | |
| 휴대전화 스크린샷 (최소 2장) | |
| 개인정보처리방침 URL | |
| 콘텐츠 등급 | |
| 타겟층 설정 | |
| 광고 포함 여부 | 예 |

> 각 항목의 구체적인 작성 요강은 [PLAY_STORE_RELEASE_GUIDE.md](./PLAY_STORE_RELEASE_GUIDE.md) 6절을 참조합니다.

### 3.3 프로덕션 AAB 업로드

```
Play Console 좌측 메뉴
└── 앱 (기업족보)
    └── 릴리스
        └── 프로덕션
            └── [새 버전 만들기]
                └── App Bundle → app-release.aab 업로드
```

업로드 후 항목 작성:

| 항목 | 입력 예시 |
|------|-----------|
| 버전 이름 | 1.0.0 |
| 출시 노트 | 기업족보 v1.0.0 첫 출시. 92개 대규모기업집단 정보, 지주회사 구조 시각화, 주주현황 조회 기능 제공. |

### 3.4 심사 제출

모든 필수 항목이 완료된 상태임을 확인한 후 **[검토를 위해 앱 제출]** 클릭합니다.

- 심사 기간: 첫 출시의 경우 보통 **3~7일**
- 심사 결과는 Play Console 알림 및 등록된 이메일로 전달됩니다.

### 3.5 출시 후 확인

- [ ] Play Store에서 앱 검색 및 다운로드 확인
- [ ] 실제 광고 (배너)가 정상 표시되는지 확인
- [ ] AdMob Console에서 앱 스토어 연결
- [ ] Play Console 대시보드에서 다운로드 수, 평점 모니터링

## 버전 코드 관리

각 단계마다 빌드를 올릴 때 `versionCode`를 증가시켜야 합니다.

파일: `packages/web/android/app/build.gradle`

```gradle
defaultConfig {
    versionCode 1        // 내부테스트: 1, 비공개: 2, 프로덕션: 3 (매번 1씩 증가)
    versionName "1.0.0"  // 내부테스트: "0.1.0", 비공개: "0.2.0", 프로덕션: "1.0.0"
}
```

> 같은 `versionCode`의 빌드를 다시 업로드하면 오류가 발생합니다.

## 문제 해결

### Q: 비공개 테스트에서 심사가 거부되었어요
**A:** 거부 사유를 확인하여 수정한 후 재제출합니다. 스토어 등록정보의 필수 항목이 비어있는 경우에도 거부될 수 있습니다.

### Q: 프로덕션 제출이 차단되고 있어요
**A:** 신규 계정의 경우 비공개 테스트에서 최소 20명이 2주 이상 참여해야 합니다. 비공개 테스트 화면에서 참여 현황과 경과 일수를 확인하세요.

### Q: 테스트자가 앱을 다운로드할 수 없어요
**A:** 테스트자가 opt-in (참여 신청)을 완료했는지 확인합니다. 링크를 열었을 때 "테스트자로 참여" 단계를 건너뛴 경우에 해당합니다.

### Q: 내부테스트와 비공개 테스트 동시에 진행 가능할까요?
**A:** 네, 각 트랙은 독립적으로 운영됩니다. 내부테스트로 빠른 피드백을 받고, 비공개 테스트는 프로덕션 출시 요구사항(20명/2주) 충족을 위해 병행할 수 있습니다.
